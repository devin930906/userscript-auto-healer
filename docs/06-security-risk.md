# 安全与风险控制

> 状态：设计完成、测试未执行，真实风险缓解还待验证。

## 信任边界
不可信：用户导入 .user.js、@require、DOM/iframe/页面日志、AI 候选、外部 PR；需明确界限：应用主进程/渲染进程/自管 Chrome+扩展/目标网站/本地文件系统/外部 AI/CI 发布权限。

## 权限模型
Chrome 仅回环调试，不共享日常默认 Profile；必须验证实例和页面目标归属，拒绝占用端口误连；只可终止本工具管理的 Chrome；不提升权限、不绕过登录、浏览器或网站隔离。写入只在已授权脚本路径且先备份；默认禁止 AI 外发及自动覆盖。

## 数据保护
密钥、Cookie、页面用户资料和源脚本可能敏感，普通日志只记录必要摘要、路径脱敏、Error 类型与证据引用；每次 AI 调用需检查用户允许字段/成本限制，默认不得发送全 DOM、Cookie、凭据、私人内容。

## 凭据处理
API Key 采用 Windows 安全存储或经用户批准的受保护方式，便携场景需另验证；无密钥时不默默降级到无认证服务。禁止仓库/CI/日志包含凭据。Electron 渲染进程禁用 Node Integration、启用 contextIsolation，preload 仅提供固定类型化 IPC 接口。

## 外部依赖风险
AST、Chrome 自动化、管理器适配、ZIP 打包工具及 npm 第三方 Actions 逐个核对版本、许可证、供应链；外部 PR 不执行写权限发布；未验证安装脚本/可执行文件不得在 CI 作为可信依赖。

## 预防措施
以上措施均须由测试验证后才能标记已受控，不能因已记录风险就视为消除。文件覆盖、权限变化和浏览器安全策略是禁止绕过的硬边界。

## 恢复措施
备份和操作日志用于可验证回滚；不拥有的浏览器进程只断开；取消 AI 后禁用后续调用并保留脱敏审计；出现敏感数据外发风险应提示用户撤销凭据并及时更换。

## 验证要求
严重风险的负例测试、真实 Windows 运行、依赖许可审查和 ZIP 完整性验证必须作为发布阻断项；第三方服务条款/数据保护适用范围为“需二次核查”。

# 使用体验与操作契约

> 状态说明（2026-11-05）：本文件保留原开发准备阶段的使用体验契约；原先“尚未有正式运行 UI”的结论属于 2026-10-18 历史状态。当前仓库已有 Electron/TypeScript 桌面渲染界面与阶段性 Windows Electron 测试证据，但 TASK-017 的完整用户旅程与相关 TEST/GATE 尚未验收。以下早期“拟提供”项目是已批准的设计目标，不等于现有界面全部实现。

## 用户入口
本地应用拟提供“脚本库 / 浏览器 / 诊断与修复 / 任务 / 版本与回滚 / 健康监控 / 设置”。不把任意 shell 权限交给渲染界面。

## 首次运行
展示不可绕过网页/浏览器权限、默认只生成候选且不覆盖原文件→选 Chrome.exe 或便携版→配置非默认专用调试 Profile→确认仅使用 127.0.0.1 回环地址、默认 CDP 端口 9896（可配置，须检查端口占用和实际监听归属；历史 9223 仅为 PoC 示例）→独立检查版本、目录占用、浏览器归属→核对扩展管理器、脚本安装状态及 GM API；Chrome 138+ 必须核对扩展详情页中用户主动授权的 Allow User Scripts 开关→AI 可选且默认关闭。缺扩展时只允许静态/部分动态诊断。

## 主要操作流程
普通用户主流程：选择受支持的 Chrome/Chrome++ 与获授权、可安全使用的 Data/Profile→多选/拖入/选择目录批量导入 .user.js→一次启动受控流程→逐脚本自动预检元数据、AST、@match/依赖/GM API，按已配置或可可靠发现的场景开展真实 DOM/业务诊断→按本地优先生成最小修复候选，可选在明确配置及授权后调用 AI→在同一受控 Chrome 和真实 Tampermonkey 中验证修复前失败、修复后业务恢复→仅在已取得必要授权和可信证据时执行备份、版本更新及受控提交/回滚→展示每项结果、错误原因、候选与历史。普通主流程不得强制逐脚本填写选择器、进入手动 GM 测试夹具或人工修改修复候选；目标 URL、登录条件、业务动作与断言无法可靠发现或未配置、权限或管理器能力不足时，逐脚本报告 UNKNOWN/受阻，保留原件且不宣称修复成功，其他独立脚本继续。浏览器、扩展及脚本安装仍须遵守各自真实授权与用户确认；历史人工审核/导出流程仅作为独立受限工具，不代替产品自动修复验收。

## 输入输出
输入脚本文件、Chrome 和 Profile 路径、端口、目标 URL、测试断言、可选 AI 模型服务设置；输出故障分类、诊断日志、修复候选、测试证据、批处理状态、版本差异、可回滚备份与导出文件。对外 AI 数据预览必须显示包含字段与接受方。

## 状态反馈
严格区分未检测、找到元素但业务未验证、已真实验证恢复、仍失效、无法确认和被安全策略阻断。进度显示逐脚本执行阶段、取消与重试状态；历史状态标明验证时的网页/浏览器版本与时间。

## 错误提示
端口占用：提示换端口，不接管；默认/占用 Profile：提供建新 Profile 的安全操作；扩展缺失/权限不足：明确预检失败；网站需要登录：等待用户授权环境或返回未知；AST 动态表达式：运行时确认；AI 错误：本地模式继续；备份失败：禁止保存。

## 取消与恢复
取消时不产生半成品替换；恢复任务须对脚本源 Hash、操作 ID、备份状态和场景前提重新核验，拒绝重复应用；回滚前预览版本与差异，冲突时不静默覆盖。

## 交互验收
操作由 TEST-001/002/006/007/008/017/018/020/021/022/023 证明；界面外观不会代替实际授权/测试。若最终采用 CLI，需转化为等价指令、退出码、错误输出与授权契约，不能自动扩大产品范围。


## 2026-11-05 新版（4）/（7）UI/UX 工程续接基线

### 已有实现与证据边界

- 当前 Electron 桌面界面主要位于 `app/ui/index.html`、`app/ui/index.ts`，受 `app/preload/index.ts` 与 `app/main/index.ts` 的原生 IPC、安全边界约束。不能把此 HTML 渲染界面视为独立联网网页应用或直接授予 Node/文件系统权限。
- 当前源码中的单页区块包含：.user.js 导入与进度；测试场景登记、只读诊断与观察历史；人工候选导出；带原生确认的手动恢复；可选 AI 查询；独立 Chrome/CDP 与隔离 GM 测试。已存在真实按钮、输入与状态区域，但各功能的**最终产品级验收**分别依赖既有 TASK 与 TEST，不得由界面存在推断完成。
- `app/ui/index.html` 已使用 HTML 标签、关联表单、部分 `aria-live` 状态反馈及原生控件；当前所读 HTML 未引用独立样式表。上述仅是源码静态观察，**并未在本次迁移中完成实际界面渲染、视觉对比、无障碍辅助技术测试、Windows 多缩放比测试或最终人工操作验收**。
- 正式产品需求仍以 `docs/02-requirements.md`、本文件、`docs/07-testing.md`、`docs/08-release.md` 与原有 ADR 为准；不得因缺少独立 `PRODUCT.md` / `DESIGN.md` 就宣告没有既有 UI 或自动新建另一套相互冲突的设计权威。

### 设计与交互继续开发的边界

- 使用 Impeccable Web 的适用 UI/UX 方法进行**有证据的局部审查与改进**，并由 Superpowers 控制实施和验证流程、ECC Web 补充 Electron/TypeScript/安全及测试约束。只在对应 GUI TASK/Issue 真正需要时调用，不把插件存在当作 UI 已修改或测试已通过。
- 首要设计目标是任务可理解性和误操作防护：区分只读检测、未经验证线索、人工审核候选、原生授权写入、实际 Tampermonkey/业务验证；未知或失败不得显示为恢复成功；危险操作的原生确认和默认拒绝不能因视觉调整而减少。
- 在既有信息结构内审查导入进度、部分完成、取消、重试、权限拒绝、超时、重复提交、恢复意图与中断后的状态；明确每个按钮的可用条件、反馈与下一步。界面优化不得自行赋予自动安装、自动补丁、未知来源脚本执行或自动回滚能力。
- 对现有长单页流程按真实任务审查阅读顺序、信息层级、状态消息与说明密度，并核对键盘焦点、标签、控件禁用状态、错误提示、Windows 窗口尺寸和缩放；未经真实渲染或测试的项目保持“待验证”，纯审美建议不能自动升级为 Stable 阻断项。
- 保留当前技术架构和既有有效代码。若后来批准视觉风格、设计令牌或布局规范，先记录在本文件并映射相关测试，不以技能默认模板擅自整体重设计。

## TASK-017 深色控制台

- 用户选定「18 深靛霓虹」与「深色控制台」。主区使用深靛蓝 `#111b3a`，操作面板使用 `#19274d`，主要按钮使用亮青绿 `#66f3df`，辅助图标使用浅蓝紫 `#a9affb`。手动恢复继续以琥珀色标示写入风险。

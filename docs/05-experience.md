# 使用体验与操作契约

> 状态：体验流程草案。尚未有正式运行 UI，Windows GUI 技术方案仍需确认。

## 用户入口
本地应用拟提供“脚本库 / 浏览器 / 诊断与修复 / 任务 / 版本与回滚 / 健康监控 / 设置”。不把任意 shell 权限交给渲染界面。

## 首次运行
展示不可绕过网页/浏览器权限、默认只生成候选且不覆盖原文件→选 Chrome.exe 或便携版→配置非默认专用调试 Profile→确认 127.0.0.1 与 9223 或其他空闲端口→独立检查版本、目录占用、浏览器归属→核对扩展管理器与脚本状态→AI 可选且默认关闭。缺扩展时只允许静态/部分动态诊断。

## 主要操作流程
多选/拖入/选择目录→预检 .user.js→查看 @match/依赖/GM API→补充目标 URL、登录条件及用户业务动作+预期结果→启动获授权的 Chrome→静态+真实页面诊断→展示出错源码位置与证据/盲区→按本地优先生成最小补丁→可选明确同意调用 AI→查看差异→在真实管理器中验收→备份并按策略保存或仅导出→独立确认脚本管理器内版本是否已经更新。

## 输入输出
输入脚本文件、Chrome 和 Profile 路径、端口、目标 URL、测试断言、可选 AI 模型服务设置；输出故障分类、诊断日志、修复候选、测试证据、批处理状态、版本差异、可回滚备份与导出文件。对外 AI 数据预览必须显示包含字段与接受方。

## 状态反馈
严格区分未检测、找到元素但业务未验证、已真实验证恢复、仍失效、无法确认和被安全策略阻断。进度显示逐脚本执行阶段、取消与重试状态；历史状态标明验证时的网页/浏览器版本与时间。

## 错误提示
端口占用：提示换端口，不接管；默认/占用 Profile：提供建新 Profile 的安全操作；扩展缺失/权限不足：明确预检失败；网站需要登录：等待用户授权环境或返回未知；AST 动态表达式：运行时确认；AI 错误：本地模式继续；备份失败：禁止保存。

## 取消与恢复
取消时不产生半成品替换；恢复任务须对脚本源 Hash、操作 ID、备份状态和场景前提重新核验，拒绝重复应用；回滚前预览版本与差异，冲突时不静默覆盖。
